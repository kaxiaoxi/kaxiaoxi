# 卡小西 · 代码规范

| 项目 | 内容 |
|---|---|
| 版本 | v1.0（强制） |
| 适用 | 小程序端、云函数、脚本；以及所有参与编码的 AI |
| 依据 | 微信小程序官方文档 + 本项目既定架构 |
| 配套 | [04-开发指南.md](./04-开发指南.md)、[06-Git协作规范.md](./06-Git协作规范.md) |

> **效力**：标「必须 / 禁止」的条款为强制项，Code Review 发现即打回；标「建议」的为推荐项。  
> **优先级**：微信官方文档 > 本规范 > 个人习惯。官方文档与本文冲突时，以官方为准并提 issue 修订本文。

---

## 1. 总原则

1. **不造轮子**：能用官方组件/API 就不自己实现；能用云开发就不引第三方后端。
2. **不引依赖**：新增 npm 包必须说明理由、体积影响、是否可在小程序端运行，经负责人同意。
3. **单一职责**：一个页面只做一件事；一个云函数 action 只做一件事。
4. **显式优于隐式**：命名写清楚，不写 `data1`、`temp`、`obj`。
5. **安全默认**：客户端永远不可信；敏感判断一律在云函数。

## 2. 目录与文件命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 目录 | kebab-case | `task-detail/`、`date-picker/` |
| 页面 | 目录 + `index.*` | `pages/task/detail/index.js` |
| 组件 | kebab-case 目录 + `index.*` | `components/task-card/index.js` |
| JS 文件 | kebab-case | `api.js`、`date-utils.js` |
| 图片 | kebab-case + 用途 | `icon-camera.png`、`empty-task.png` |
| 云函数 | kebab-case | `api`、`cron`、`init` |

**禁止**：中文文件名、空格、大写开头目录、`新建文件夹`、`test2.js`。

## 3. JavaScript

### 3.1 基础

- 必须 `const` / `let`，**禁止 `var`**；
- 必须 `===` / `!==`，禁止 `==`；
- 字符串用单引号；不加分号（Prettier 已配置）；
- 缩进 2 空格；行宽 100；
- 模块用 CommonJS（`require` / `module.exports`），与小程序运行时一致。

### 3.2 命名

| 类型 | 规则 | 示例 |
|---|---|---|
| 变量 / 函数 | camelCase | `taskList`、`loadDetail()` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY`、`SIGNUP_STATUS` |
| 类 / 构造函数 | PascalCase | `TaskService` |
| 布尔 | `is/has/can` 前缀 | `isLoading`、`hasMore` |
| 事件回调 | `on` + 动作 | `onTapApply`、`onChangeDate` |
| 私有方法 | 下划线前缀（仅页面内） | `_fetchList()` |

### 3.3 异步

```js
// 必须：async/await + try/catch
async loadDetail(id) {
  try {
    const data = await call('task.detail', { id })
    this.setData({ detail: data })
  } catch (err) {
    console.error('[task.detail]', err)
    wx.showToast({ title: err.message || '加载失败', icon: 'none' })
  }
}
```

**禁止**：裸 `Promise.then` 链超过两层；回调地狱；`setTimeout` 模拟等待。

### 3.4 模块边界

| 目录 | 允许放什么 | 禁止放什么 |
|---|---|---|
| `utils/` | 纯函数，无 `wx.*` 调用 | 网络请求、页面跳转 |
| `services/` | 云函数调用封装 | 业务 UI 逻辑 |
| `pages/` | 页面状态与交互 | 可复用业务逻辑（抽到 services/utils） |
| `components/` | 展示与事件抛出 | 直接调云函数 |

## 4. 页面与组件

### 4.1 页面四件套

每个页面必须有 `index.js / index.json / index.wxml / index.wxss`，`index.json` 至少包含标题：

```json
{ "navigationBarTitleText": "任务详情" }
```

### 4.2 Page 结构顺序

固定顺序，便于 review：

```js
Page({
  data: {},           // 1. 数据
  onLoad() {},        // 2. 生命周期
  onShow() {},
  onUnload() {},
  // 3. 事件处理（onXxx）
  // 4. 私有方法（_xxx）
  // 5. 工具方法
})
```

### 4.3 组件

- 必须声明 `properties` 类型与默认值；
- 必须用 `triggerEvent('change', detail)` 向外抛事件，不直接改父级数据；
- 组件不直接调用云函数，数据由页面传入。

```js
Component({
  properties: {
    task: { type: Object, value: null },
    showStatus: { type: Boolean, value: true }
  },
  methods: {
    onTap() {
      this.triggerEvent('select', { id: this.data.task._id })
    }
  }
})
```

### 4.4 页面跳转

统一封装（建议放 `utils/nav.js`）：

```js
function go(url) {
  wx.navigateTo({ url })
}
```

- TabBar 页面用 `wx.switchTab`；
- 登录后首页用 `wx.reLaunch`；
- 参数用 query，禁止传大对象；复杂参数传 ID，详情页再查。

## 5. setData 与性能

1. **只 set 变化的字段**，禁止 `this.setData(this.data)`；
2. 深层字段用路径：

```js
this.setData({ 'detail.status': 'approved' })
```

3. 列表分页每次 20 条，用 `list.concat(newItems)`，禁止全量替换大数组；
4. 单次 `setData` 数据量必须 < 1MB（官方上限 1024KB）；
5. `wx:for` 列表项多时使用 `recycle-view` 或分页，不要一次渲染 500 条；
6. 图片必须 `lazy-load`，列表缩略图走云存储图片处理参数；
7. 禁止在 `onPageScroll` 里 `setData`。

## 6. WXML

### 6.1 必须

- `wx:for` 必须带 `wx:key`（用唯一字段，不用 index）；
- 复杂表达式放 JS，WXML 只做简单判断与渲染；
- 事件绑定用 `bindtap`，需要阻止冒泡才用 `catchtap`；
- 自定义组件事件用 `bind:change`；
- 文本用 `<text>`，容器用 `<view>`，可滚动区域用 `<scroll-view>`。

```html
<view class="task-card" wx:for="{{tasks}}" wx:key="_id" bindtap="onTapTask" data-id="{{item._id}}">
  <text class="task-card__title">{{item.title}}</text>
</view>
```

### 6.2 禁止

- 在 WXML 里写 `{{a + b + c}}` 之外的复杂运算、函数调用；
- 用 `hidden` 隐藏大块 DOM（用 `wx:if`）；
- 内联 `style` 写死颜色（用 class + 变量）；
- 空 `class=""`、无意义嵌套超过 4 层。

## 7. WXSS

| 规则 | 说明 |
|---|---|
| 单位 | 布局用 `rpx`，边框用 `1rpx`，字体可 `rpx` |
| 变量 | 颜色/圆角统一用 `styles/variables.wxss` 的 CSS 变量 |
| 类名 | BEM-lite：`block__element--modifier`，如 `task-card__title` |
| 选择器 | 最多 3 层，禁止标签选择器做主要样式 |
| `!important` | 禁止（覆盖第三方组件时需注释说明） |
| 全局样式 | 只放 reset 与变量，业务样式写在页面/组件内 |

```css
.task-card {
  background: var(--card);
  border-radius: var(--radius);
  padding: 28rpx;
}

.task-card__title {
  font-size: 32rpx;
  font-weight: 600;
}
```

## 8. 云函数

### 8.1 结构

- 单入口 `api`，按 `action` 路由；
- 每个 action 必须声明：**谁能调、能看哪些数据、参数校验**；
- 返回结构固定：

```js
// 成功
{ code: 0, data: {} }
// 失败
{ code: 40301, message: '无权限' }
```

### 8.2 错误码段

| 段 | 含义 |
|---|---|
| `400xx` | 参数错误 / 业务校验失败（如 40001 名额已满） |
| `403xx` | 无权限 |
| `404xx` | 资源不存在 |
| `409xx` | 状态冲突（如重复报名） |
| `429xx` | 频率限制 |
| `500xx` | 未知异常 |

### 8.3 必须

```js
const { OPENID } = cloud.getWXContext()   // 只信这个，不信 event.openid
```

- 参数先校验再查库；
- 写操作前校验角色与数据归属；
- 涉及名额、状态流转的写操作使用事务；
- 日志格式：`console.error('[api] action=task.apply openid=xxx err=', err)`，openid 只打后 6 位；
- 单次云函数默认 3s，批量任务分批处理并记录游标。

### 8.4 禁止

- 在云函数里 `eval`、动态拼接查询条件；
- 把 `event` 原样写进数据库；
- 一次查询超过 100 条不翻页；
- 在 `api` 里做定时任务（放 `cron`）。

## 9. 数据库

| 项 | 规范 |
|---|---|
| 集合名 | 小写复数，下划线分隔：`task_signups` |
| 字段名 | camelCase：`startAt`、`publisherOpenid` |
| 时间 | 一律 `db.serverDate()`，禁止客户端时间 |
| 主键 | 用 `_id`；业务唯一键建唯一索引（如学号） |
| 删除 | 软删除（`status` / `cancelledAt`），禁止物理删除业务数据 |
| 权限 | 客户端零直连，9 张集合全部「所有用户不可读写」 |
| 事务 | 报名、审核、请假递补、移除名单必须走事务 |
| 计数 | 冗余计数与明细同事务更新 |

**禁止**：在客户端 `wx.cloud.database()` 直接读写。

---

## 10. 安全与隐私

1. 学号、电话、宿舍属于个人信息，**只在云函数按角色返回**，前端不缓存到 storage；
2. 列表接口默认脱敏，详情接口按关系返回；
3. 用户输入（任务标题、详情、待办、请假原因）必须过 `security.msgSecCheck`；
4. 不得在日志、埋点、错误上报中出现完整手机号/学号；
5. 隐私政策与实际收集字段保持一致，新增字段先改文档。

---

## 11. 错误处理与提示

- 网络/云函数错误必须给用户可见反馈（`wx.showToast` 或页面错误态），禁止静默失败；
- `catch` 里必须 `console.error` 带上下文，不允许空 `catch`；
- 错误文案面向用户，不暴露堆栈与错误码；
- 关键路径（报名、请假、发布）失败后要能重试，且不产生脏数据。

---

## 12. 注释

- 每个云函数 action 上方一行说明：做什么、谁能调；
- 复杂业务规则（候补递补、二课统计口径）必须写注释并注明来源文档章节；
- 禁止无意义注释：`// 设置数据`、`// 循环`；
- `TODO` 必须带负责人与日期：`// TODO(zhangsan 2026-12-01): 接入内容安全`。

## 14. AI 协作规则（给模型 / 助手）

> 本节是给 ChatGPT、Claude、DeepSeek、Copilot 等模型看的硬性约束。人类开发者同样适用。

### 14.1 开工前必须

1. 读 `docs/01-需求与设计.md`、`docs/03-数据库设计.md`、本文件；
2. 确认改动落在哪个模块，列出要改的文件清单；
3. 若涉及新字段/新接口，先改 `docs/03` 或 `docs/02`，再改代码。

### 14.2 允许修改

- `miniprogram/**`（页面、组件、services、utils、styles）
- `cloudfunctions/**`
- `docs/**`（与本次改动相关的文档）

### 14.3 禁止修改（除非人类明确要求）

- `project.config.json` 的 `appid`、`miniprogramRoot`、`cloudfunctionRoot`
- `app.json` 的页面顺序与 TabBar 数量
- `design/**`、`assets/**`
- 数据库字段名与枚举值（必须先改文档）
- 任何 `package.json` 的依赖版本（新增依赖需人类批准）

### 14.4 编码约束

- 只用官方组件与 API；不引入 UI 框架；
- 不写 `console.log`，调试信息用 `console.warn/error`；
- 不生成未注册的页面、未鉴权的 action；
- 不把业务规则写死在前端（名额、权限、状态判断以云函数为准）；
- 生成代码必须能通过 ESLint；缩进、引号、分号遵循 `.prettierrc`；
- 一次只做一件事，不顺手重构无关文件。

### 14.5 输出要求

1. 先给「改动清单」（文件 + 目的），再给代码；
2. 说明是否需要重新部署云函数、是否要改数据库索引；
3. 附自检结果：ESLint、页面注册、鉴权、边界情况；
4. 不确定的业务规则**先问，不要猜**；
5. 提交信息按 [06-Git协作规范.md](./06-Git协作规范.md) 的格式给出一行。

### 14.6 可直接复制的提示词

```text
你在「卡小西」微信小程序项目中工作。开始前请阅读：
- docs/05-代码规范.md（强制）
- docs/03-数据库设计.md（字段以它为准）
- docs/01-需求与设计.md（业务规则）

硬性要求：
1. 只用微信官方组件/API 与 CommonJS，不引入新依赖；
2. 客户端不直连数据库，所有数据经 callFunction('api', {action, payload})；
3. 新 action 必须在 cloudfunctions/api 的 router 注册并做角色/数据范围校验；
4. 禁止 console.log；禁止修改 project.config.json、app.json 页面顺序、design/、assets/；
5. 新字段先改 docs/03，再改代码；
6. 输出：改动清单 → 代码 → 自检（ESLint/页面注册/边界） → 一行 commit message。
```

## 15. 附录：反例对照

| 反例 | 问题 | 正确写法 |
|---|---|---|
| `var list = []` | 变量提升、作用域混乱 | `const list = []` |
| `wx.cloud.database().collection('tasks').get()` | 客户端直连 | `call('task.list', {...})` |
| `this.setData({ list: this.data.list })` | 无意义全量刷新 | 只 set 变化字段 |
| `wx:key="index"` | 列表复用错乱 | `wx:key="_id"` |
| `console.log('进来了')` | 调试残留 | 删除或用 `console.warn` |
| `if (role == 'admin')` | 弱类型比较 | `if (role === 'admin')` |
| `catch (e) {}` | 吞异常 | 记录并提示用户 |
| `style="color:#2E5F7E"` | 硬编码颜色 | class + CSS 变量 |
| 云函数里 `event.openid` | 可伪造 | `cloud.getWXContext().OPENID` |
| 一次 `get()` 取 1000 条 | 超限/超时 | 分页 100 条循环 |
