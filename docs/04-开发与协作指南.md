## 2. 第一次配置（约 15 分钟）

### 2.1 验证 Git

打开 PowerShell：

```bash
git --version
```

出现版本号即成功。

### 2.2 设置身份

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

### 2.3 克隆仓库

选一个**无中文、无空格**的目录：

```bash
cd /d D:\code
git clone https://github.com/kaxiaoxi/kaxiaoxi.git
cd kaxiaoxi
```

第一次要求输密码时，**填 GitHub Personal Access Token**（不是登录密码）：

> GitHub → 头像 → Settings → Developer settings → Personal access tokens（classic）→ Generate new token → 勾 `repo` → 复制。

> 国内网络访问 GitHub 可能被重置。若 clone 失败，先打开代理，再执行：
>
> ```bash
> git config --global http.https://github.com.proxy http://127.0.0.1:7890
> ```
>
> 端口按你本机代理改（Clash 常见 7890 / 7897）。

### 2.4 安装检查工具（可选）

```bash
npm install
```

装好后 `npm run check` 能检查代码格式，提 PR 前跑一次。

## 3. 在开发者工具里跑起来

### 3.1 导入

1. 打开微信开发者工具，用**有权限的微信**扫码登录；
2. 「导入项目」；
3. 目录选 `D:\code\kaxiaoxi`（有 `project.config.json` 的那层，**不要**选 `miniprogram`）；
4. AppID 自动带出，不用改；
5. 后端服务选「微信云开发」。

### 3.2 部署云函数（第一次必做）

左侧 `cloudfunctions` 下有 `api`、`cron`、`init` 三个文件夹，对**每一个**右键 →「上传并部署：云端安装依赖」。

> 以后只要改了 `cloudfunctions/` 里的代码，都要重新部署一次，否则线上还是旧逻辑。

### 3.3 验证

点「编译」，模拟器出现「首页 / 任务 / 年历 / 我的」四个 Tab 即成功。第一次调接口会自动建数据库集合。

## 4. 分支与提交（核心）

### 4.1 分支模型

```
main       ← 可发布，只接受 develop 合并
 └── develop ← 日常集成分支
      ├── feature/xxx  功能
      ├── fix/xxx      修 bug
      └── docs/xxx     文档
```

- 任何人**不直接在 `main` / `develop` 上改代码**；
- 每个任务开一个分支，合并后删除。

### 4.2 分支命名

```
feature/<模块>-<简述>     feature/task-manage
fix/<问题简述>            fix/signup-count
docs/<内容>               docs/onboarding
```

全小写、用 `-` 分词，不超过 4 段。

### 4.3 标准流程（照抄即可）

```bash
# 1. 同步最新
git checkout develop
git pull

# 2. 开分支
git checkout -b feature/xxx

# 3. 让 AI 改代码（见第 5 节）

# 4. 检查
npm run check

# 5. 提交
git add .
git commit -m "首页增加活动横幅"

# 6. 推送
git push -u origin feature/xxx

# 7. 去 GitHub 提 PR（见 4.5）

# 8. 合并后清理
git checkout develop
git pull
git branch -d feature/xxx
```

### 4.4 提交信息

一句话说明这次改了什么就行，中文即可：

```bash
git commit -m "首页增加活动横幅"
git commit -m "修复报名人数不更新"
```

不用记格式，也不用管前缀，能看懂即可。

### 4.5 提 PR

1. 打开 https://github.com/kaxiaoxi/kaxiaoxi ；
2. 点「Compare & pull request」，或左侧「Pull requests」→ New pull request；
3. 源分支 `feature/xxx`，目标分支 `develop`；
4. 描述写清楚：**改了什么、怎么测的、影响哪些页面**；
5. 合并方式选 **Squash and merge**，然后点「Delete branch」；
6. `develop` 没有保护，成员可以自己合并；`main` 只有负责人能合。

### 4.6 遇到冲突

```bash
git pull --rebase
# 打开冲突文件，保留正确内容
git add <冲突文件>
git rebase --continue
git push --force-with-lease
```

冲突涉及 `app.json`、`project.config.json` 时先问负责人。

### 4.7 发版（仅负责人）

```bash
git checkout main
git merge --no-ff develop -m "chore: release vX.Y.Z"
git tag -a vX.Y.Z -m "vX.Y.Z 说明"
git push origin main --tags
```

然后在开发者工具「上传」→ 公众平台「提交审核」→ 发布。

## 5. 用 AI 写代码的正确姿势

### 5.1 先让 AI 读规则

把这三份文件丢给 AI（或让它自己读仓库）：

1. `AGENTS.md` —— 硬性禁止项
2. `docs/05-代码规范.md` —— 命名、结构、云函数写法
3. `docs/03-数据库设计.md` —— 字段以它为准

AI 读不到仓库时，把 `AGENTS.md` 全文粘进对话开头。

### 5.2 一次只做一个功能

- 一次对话只改一个页面或一个接口；
- 别让 AI「顺便重构整个项目」；
- 改完一个功能就提交一次，方便回滚。

### 5.3 改完必须自己验证

AI 说「已完成」不等于能跑。你必须：

1. 重新编译；
2. 点一遍主流程（不是只看编译通过）；
3. 看「调试器 → Console」有没有红色报错；
4. 改了云函数就重新部署再测。

### 5.4 云函数不会热更新

改了 `cloudfunctions/**` 必须：

> 右键对应函数 →「上传并部署：云端安装依赖」

否则前端调用的还是旧代码，这是新手最容易卡住的地方。

### 5.5 不要让 AI 碰的东西

- `project.config.json` 的 `appid`、`miniprogramRoot`
- `app.json` 的页面顺序与 TabBar 数量
- `design/`、`assets/`（设计稿）
- 数据库字段名与枚举（要先改 `docs/03`）

### 5.6 标准收尾话术（成员自己合并到 develop）

改完把下面这段发给 AI：

```text
改完先运行 npm run check，通过后提交并推送到 origin 的当前分支。
然后在 GitHub 上向 develop 创建 Pull Request，标题用一句中文说明改了什么。
合并方式选 Squash and merge，合并后删除分支。
不要动 main，也不要直接往 develop 推代码。
```

规则：

- 功能分支 → PR → **Squash 合并**进 `develop`（`develop` 未设保护，成员可自行合并）；
- `main` 只有负责人能合，用于发版；
- 合并后删掉功能分支，保持仓库干净。

## 6. 常见问题

**Q1：导入提示「无权限」**
让负责人把你的微信加为小程序开发者，重新扫码。

**Q2：编译后一片空白**
看 Console 第一行红色报错。常见原因：页面没在 `app.json` 注册、`require` 路径错、改完没点编译。

**Q3：接口报「服务异常」**
云函数没部署或部署失败，重新「上传并部署」。

**Q4：云函数改了没生效**
见 5.4，必须重新部署。

**Q5：数据库报 collection not exists**
第一次调用会自动建；还报就跑一次 `init` 云函数。

**Q6：push 要求输密码**
填 GitHub Personal Access Token。

**Q7：push 被拒绝（rejected）**
别人先推了：

```bash
git pull --rebase
git push
```

**Q8：改错了想撤销（未提交）**
`git checkout -- 文件路径`

**Q9：误提交了不该提交的文件**
`git rm --cached 文件路径`，再提交一次。

**Q10：真机没效果**
点「预览」扫码；检查手机网络与云环境。
