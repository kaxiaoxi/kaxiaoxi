## 2. 首次配置（新人 30 分钟上手）

### 2.1 拉代码

```bash
git clone <仓库地址> kaxiaoxi
cd kaxiaoxi
```

### 2.2 导入开发者工具

1. 打开微信开发者工具 → 「导入项目」；
2. 目录选择仓库根目录（含 `project.config.json` 的那一层）；
3. AppID 填影协的小程序 AppID；没有权限时先用「测试号」；
4. 确认 `miniprogramRoot = miniprogram/`、`cloudfunctionRoot = cloudfunctions/` 已被识别。

### 2.3 配置云环境

```bash
# 复制模板
cp miniprogram/env.example.js miniprogram/env.js
```

编辑 `miniprogram/env.js`：

```js
module.exports = {
  envId: 'kaxiaoxi-prod-xxxxxx'
}
```

> `env.js` 已被 `.gitignore` 忽略，**禁止提交**。

### 2.4 安装云函数依赖

开发者工具里对 `cloudfunctions/api`、`cron`、`init` 分别右键 →「在终端中打开」，执行：

```bash
npm install
```

或者在根目录：

```bash
cd cloudfunctions/api && npm install
cd ../cron && npm install
cd ../init && npm install
```

### 2.5 初始化云开发

1. 开发者工具 → 云开发 → 开通（选按量或套餐）；
2. 右键 `cloudfunctions/init` →「上传并部署：云端安装依赖」；
3. 云开发控制台 → 云函数 → `init` → 测试，返回 `{ code: 0, data: { created: [...] } }`；
4. 按 [03-数据库设计.md](./03-数据库设计.md) 在控制台建索引、把 9 张集合权限改为「所有用户不可读写」。

### 2.6 跑起来

编译后进入启动页，`auth.login` 返回后跳首页。看到「首页 / 任务 / 年历 / 我的」四个 Tab 即配置成功。

## 3. 目录结构

```
kaxiaoxi/
├── project.config.json          # 工程配置（提交）
├── project.private.config.json  # 本地私有配置（不提交）
├── .eslintrc.js .prettierrc     # 代码规范
├── miniprogram/                 # 小程序端
│   ├── app.js / app.json / app.wxss
│   ├── env.js                   # 云环境 ID（不提交）
│   ├── sitemap.json
│   ├── pages/                   # 页面，一个页面一个目录
│   │   ├── launch/              # 启动分流
│   │   ├── home/                # 首页
│   │   ├── task/                # 任务（list/detail/edit/manage/mine）
│   │   ├── calendar/            # 年历
│   │   └── mine/                # 我的
│   ├── components/              # 自定义组件（kebab-case）
│   ├── services/                # 接口封装（api.js）
│   ├── utils/                   # 纯函数（date/constants/validate）
│   ├── styles/                  # 全局样式与变量
│   └── images/                  # 图标与 IP 素材（压缩后）
├── cloudfunctions/              # 云函数
│   ├── api/                     # 业务唯一入口（按 action 路由）
│   ├── cron/                    # 定时任务
│   └── init/                    # 一次性初始化
├── docs/                        # 需求、技术、数据库、规范
├── assets/design/               # IP 原始素材
└── design/                      # 线框图与高保真稿
```

**云函数不能跨目录共享代码**（每个函数独立打包），公共逻辑要在每个函数内各放一份，或发布成 npm 包。当前约定：`api` 内部自建 `lib/`，`cron` 需要时复制同一份。

## 4. 日常开发

### 4.1 新增一个页面

1. 建目录 `miniprogram/pages/<模块>/<页面>/`；
2. 四个文件同名：`index.js`、`index.json`、`index.wxml`、`index.wxss`；
3. 在 `app.json` 的 `pages` 注册（路径不带扩展名）；
4. 需要分包时，在 `app.json` 的 `subpackages` 中登记；
5. 页面 `json` 至少写 `navigationBarTitleText`。

### 4.2 新增一个接口

1. 在 `cloudfunctions/api/index.js` 的 `router` 注册 `'模块.动作'`；
2. 实现里先鉴权（角色 / 部门 / 任务归属），再校验参数，再操作数据库；
3. 返回 `{ code: 0, data }`；异常用 `{ code, message }` 且 `code` 按 [05](./05-代码规范.md) 的错误码段；
4. 前端通过 `services/api.js` 的 `call(action, payload)` 调用，不直接 `wx.cloud.callFunction`。

### 4.3 云函数部署

- 改动 `cloudfunctions/**` 后必须**重新上传部署**才生效；
- 依赖变化时选「上传并部署：云端安装依赖」；
- 部署后在云开发控制台查看日志，本地调试可用「云函数本地调试」。

### 4.4 调试技巧

| 场景 | 做法 |
|---|---|
| 真机 | 预览二维码；iOS/Android 各测一次 |
| 云函数 | 控制台「测试」传 `{ "action": "auth.login", "payload": {} }` |
| 数据库 | 控制台直接查集合；写操作走云函数 |
| 订阅消息 | 只能用真机测，模拟器无法授权 |
| 定时任务 | 控制台手动触发，看日志 |

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `wx.cloud is not defined` | 基础库过低 | 升级基础库到 2.2.3+ |
| `env not exists` | `env.js` 没配或环境 ID 错 | 检查云开发控制台环境 ID |
| 云函数 404 | 没部署 / 名字不一致 | 重新上传，确认函数名 `api` |
| 数据库 `permission denied` | 客户端直连 | 改走云函数 |
| 订阅消息收不到 | 未订阅 / 一次性已用完 | 重新引导订阅，只能发一条 |
| 上传图片失败 | 未压缩 / 超限 | 压缩到 500KB 内，见 02 文档 |
| 真机白屏 | 域名/调试开关 | 打开「不校验合法域名」仅限开发 |
