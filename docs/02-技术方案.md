## 1. 选型

| 层 | 选型 | 理由 |

## 5. 身份、角色与数据范围

### 5.1 登录

```
启动 → callFunction(auth.login)
→ OPENID 查 members
   ├─ 无 → state:'new' → 注册（6 项）
   ├─ pending → 待审核
   ├─ left → 已退会
   └─ active → 返回 member + 权限位
```

### 5.2 模型

```js
role: 'chairman' | 'minister' | 'member'
dept: 'photo' | 'pr' | 'ops'
status: 'pending' | 'active' | 'left'
```

### 5.3 数据范围（部长可见性的实现）

| 场景 | 判定 |
|---|---|
| 发任务 | `role !== 'member'` |
| 审核报名 / 请假 / 移除名单 | `task.publisherOpenid === OPENID` 或 `role === 'chairman'` |
| 看报名者完整资料（学号/电话/宿舍） | `role === 'chairman'`，或 `role === 'minister' && task.publisherDept === 自己 dept` |
| 看同活动成员姓名+电话 | 自己是该任务 `approved/leave_pending/left` 之一 |
| 部门待办 | 读：本部门；写：本部门部长或主席 |
| 学年/设置 | 主席 |

**实现要点**：`tasks.publisherDept` 在创建时由服务端从 `members.dept` 写入，前端不得传；所有成员资料查询在服务端拼 `dept` 条件，不做「查全表再过滤」。

### 5.4 路由与中间件

```js
const ROUTES = {
  'task.cancel':      { role: 'minister', scope: 'publisherOrChairman', handler: task.cancel },
  'member.list':     { role: 'minister', scope: 'deptOrAll', handler: member.list },
}
```

`scope`：`self` / `dept` / `publisherOrChairman` / `all`。

### 6.3 状态不落库

活动状态与报名状态都按服务器时间实时推导：

```js
function phase(task, now) {
  if (task.cancelledAt) return 'cancelled'
  if (!task.published) return 'draft'
  if (now < task.startAt) return 'not_started'
  if (now < task.endAt) return 'ongoing'
  return 'finished'
}
function signupPhase(task, now) {
  if (now < task.signupStartAt) return 'not_open'
  if (now < task.signupDeadline) return 'open'
  return 'closed'
}
// 学年：8 月 1 日为界，看活动开始时间
function academicYearOf(d) {
  const y = d.getFullYear()
  const m = d.getMonth() + 1
  return m >= 8 ? `${y}-${y + 1}` : `${y - 1}-${y}`
}
```

列表按状态筛选时用时间范围查询，而不是 `status` 字段：

```js
// 进行中
where({ published: true, cancelledAt: _.exists(false), startAt: _.lte(now), endAt: _.gt(now) })
```

### 7.2 事务：递补

```js
async function promoteNext(tx, taskId) {
  const next = await tx.collection('task_signups')
    .where({ taskId, status: 'waitlisted' })
    .orderBy('queueNo', 'asc').limit(1).get()
  if (!next.data.length) return null
  await tx.collection('task_signups').doc(next.data[0]._id)
    .update({ data: { status: 'approved', updatedAt: db.serverDate() } })
  await tx.collection('tasks').doc(taskId)
    .update({ data: { approvedCount: _.inc(1), waitlistCount: _.inc(-1) } })
  return next.data[0].openid
}
```

调用点：`signup.cancel`、`signup.reviewLeave`（通过时）、`signup.remove`（活动未开始时）。

> 云开发事务最多操作 10 个文档；本项目最多 3 个。

### 7.3 二课实时聚合（无流水表、无结算）

二课不落库，每次查询现算：

**个人明细**

```js
// 1. 我的 approved / leave_pending / left 报名
const signs = await pageAll(db.collection('task_signups')
  .where({ openid, status: _.in(['approved', 'leave_pending', 'left']) }))

// 2. 取对应任务，过滤：已结束、未取消、有学时
const tasks = await db.collection('tasks').where({
  _id: _.in(signs.map(s => s.taskId)),
  published: true,
  cancelledAt: _.exists(false),
  endAt: _.lte(now),
  erkeHours: _.gt(0)
}).get()

// 3. 明细 + 合计
const detail = tasks.data.map(t => ({ title: t.title, hours: t.erkeHours, date: t.startAt }))
const total = detail.reduce((a, b) => a + b.hours, 0)
```

**年度汇总（部长/主席）**

```js
// 1. 该学年所有已结束、未取消、有学时的任务
const tasks = await pageAll(db.collection('tasks').where({
  academicYear, published: true, cancelledAt: _.exists(false),
  endAt: _.lte(now), erkeHours: _.gt(0)
}))

// 2. 这些任务下所有 approved 报名（一次分页取回，按 taskId in 查）
const signs = await pageAll(db.collection('task_signups').where({
  taskId: _.in(tasks.map(t => t._id)), status: 'approved'
}))

// 3. 按 openid 累加
const sum = {}
for (const s of signs) sum[s.openid] = (sum[s.openid] || 0) + hoursOf(s.taskId)

// 4. join members 取姓名/学号/学院
```

**为什么可以不做流水账**：一学年 1000 条报名、200 条任务，全量扫一遍在云函数里是毫秒级；`pageAll` 每页 100，最多 10 页。数据量再大一个量级也不会有问题。

**历史准确性**：移除名单、取消任务会改变历史统计——这正是想要的（删人即扣回）。需要"冻结"时，导出 CSV 即快照。

## 8. 定时任务

`cloudfunctions/cron/config.json`：

```json
{
  "triggers": [
    { "name": "everyMinute", "type": "timer", "config": "0 * * * * * *" },
    { "name": "daily3",      "type": "timer", "config": "0 0 3 * * * *" },
    { "name": "daily4",      "type": "timer", "config": "0 0 4 * * * *" },
    { "name": "daily8",      "type": "timer", "config": "0 0 8 * * * *" }
  ]
}
```

| 任务 | 频率 | 逻辑 |
|---|---|---|
| `sendReminder` | 每分 | `reminders.status=pending && remindAt<=now` → 发订阅消息（首场前 2h） |
| `reconcile` | 每天 03:00 | 对账 `approvedCount` 与明细（**不再清理消息**，消息永久保留） |
| `cleanExpiredFiles` | 每天 04:00 | 删除 `attachments[].expiresAt <= now` 的云存储文件，`fileID` 置空、标记 `expired` |
| `autoTodo` | 每天 08:00 | 当天活动生成「现场组织」；结束次日生成「核对名单 + 收图」 |

> **没有** `openSignup` / `flowStatus` / `accrueErke`：报名开放、活动状态、二课统计都是实时算的，定时任务只负责「发提醒、建待办、对账」。

## 9. 订阅消息

| 项 | 做法 |
|---|---|
| 场景 | 活动开始前 2 小时，唯一推送场景 |
| 模板 | 「活动开始提醒」：活动名称、时间、地点、备注 |
| 授权 | 点「报名」的同一次 tap 里 `wx.requestSubscribeMessage` |
| 写入 | 同意后 `reminder.create` 写 `startAt-2h` |
| 发送 | cron 每分钟扫，`subscribeMessage.send` |
| 失败 | 43101 拒收 → failed；其他重试 1 次 → 站内兜底 |

```js
async onApply() {
  const res = await wx.requestSubscribeMessage({ tmplIds: [TMPL_ID] })
  await api('signup.apply', { taskId })
```

**做不到**：给未订阅的人推送、一次授权发多条、服务端补授权、长期订阅。

### 12.2 学年轮换（手动，8 月 1 日为界）

学年边界固定为 **8 月 1 日**，任务的 `academicYear` 由 `startAt` 推导，不靠人工填。主席只在 8 月做一次归档动作：

1. 设置页显示当前学年（按 8/1 自动算），点「开启新学年」；
2. 确认后把毕业/退会成员批量置 `left`；
3. 更新 `configs.currentAcademicYear`；
4. 主席重新指定部长；
5. 历史数据按 `academicYear` 隔离，二课汇总互不影响。

> 7 月的活动仍算旧学年，8 月 1 日起的活动自动算新学年——不需要任何额外操作，也不会出现「暑假的活动算错年份」。
